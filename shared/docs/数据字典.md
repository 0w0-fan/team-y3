# 数据字典 · spotify_songs

> 库：`spotify_dashboard`　表：`spotify_songs`　行数：32,833　引擎：InnoDB　字符集：utf8mb4
>
> 本文件对应 `shared/csv/spotify_songs_clean.csv`，由 `shared/scripts/01_clean_base.py` 产出。

## 一、字段说明

### 标识与文本

| 字段 | 类型 | 说明 | 质量提示 |
|---|---|---|---|
| `id` | BIGINT | 自增主键，导入时生成 | 数据源无主键 |
| `track_id` | VARCHAR(64) | 歌曲唯一标识 | 28,356 个唯一值，**32,833 行中有 4,477 行是同一首歌被多个歌单收录** |
| `track_name` | VARCHAR(512) | 歌曲名 | 5 行为 NULL（原表写字面量 `NA`） |
| `track_artist` | VARCHAR(512) | 歌手 | 5 行为 NULL；**未拆分合作艺人**，`&` 是乐队名分隔符不是合作标记 |
| `track_album_id` | VARCHAR(64) | 专辑唯一标识 | — |
| `track_album_name` | VARCHAR(512) | 专辑名 | 19,743 张专辑，**中位数只有 1 首** |

### 歌单分类（这是不建议删重复行的原因）

| 字段 | 类型 | 说明 |
|---|---|---|
| `playlist_name` | VARCHAR(255) | 歌单名，共 449 个 |
| `playlist_id` | VARCHAR(64) | 歌单唯一标识 |
| `playlist_genre` | VARCHAR(64) | 6 大流派：pop / latin / r&b / rap / rock / edm |
| `playlist_subgenre` | VARCHAR(128) | 24 个子流派 |

> 同一个 `track_id` 在不同歌单里，只有上面 4 个字段不同，音频特征与热度**完全一致**。
> 这 4 个字段本身就是分类维度，删掉重复行等于删掉"这首歌属于哪些歌单"的信息。

### 热度

| 字段 | 类型 | 说明 |
|---|---|---|
| `track_popularity` | TINYINT | 0–100。**0 是真实值不是缺失**，共 2,703 行 |
| `popularity_level` | VARCHAR(16) | 派生分箱：`0` / `1-20` / `21-40` / `41-60` / `61-80` / `81-100` |

### 音频特征（Spotify Audio Features，全部 0–1 除注明外）

| 字段 | 类型 | 范围 | 说明 |
|---|---|---|---|
| `danceability` | DECIMAL(10,6) | 0–1 | 舞曲性 |
| `energy` | DECIMAL(10,6) | 0–1 | 能量感 |
| `key` | TINYINT | 0–11 | 调性（0=C）。**MySQL 保留字，写 SQL 要加反引号** |
| `loudness` | DECIMAL(10,4) | 约 -60–0 | 响度 dB，通常为负 |
| `mode` | TINYINT | 0/1 | 1=大调，0=小调 |
| `speechiness` | DECIMAL(10,6) | 0–1 | 口语化程度 |
| `acousticness` | DECIMAL(10,6) | 0–1 | 原声程度 |
| `instrumentalness` | DECIMAL(12,8) | 0–1 | 器乐程度，**多数取值极小（中位数 0.0000161）**，精度特意给到 8 位 |
| `liveness` | DECIMAL(10,6) | 0–1 | 现场感 |
| `valence` | DECIMAL(10,6) | 0–1 | 情绪积极度 |
| `tempo` | DECIMAL(10,4) | BPM | 节拍速度 |
| `duration_ms` | INT | 毫秒 | 时长 |
| `duration_sec` | DECIMAL(10,3) | 秒 | 派生自 `duration_ms` |

### 日期（三列配套使用，不要单独看一列）

| 字段 | 类型 | 说明 |
|---|---|---|
| `track_album_release_date` | VARCHAR(32) | **原始字符串，未加工**，保留上游原样 |
| `release_date_std` | VARCHAR(16) | 标准化日期，**按精度保留**：`YYYY` / `YYYY-MM` / `YYYY-MM-DD` |
| `release_date_precision` | VARCHAR(8) | 精度标记：`day` 30,947 / `month` 31 / `year` 1,855 |
| `release_year` | SMALLINT | 发行年份，覆盖 1957–2020，**无缺失** |
| `release_month` | TINYINT | 发行月份，**仅 day/month 精度有值**，year 精度为 NULL |

> ⚠️ **`release_date_precision = 'year'` 的 1,855 行，`release_month` 是 NULL 不是 1。**
> 这是刻意为之：原表这些行只给了年份，补成 1 月 1 日会造出假的"每年 1 月 1 日发行高峰"。
> 按月份聚合时，请先 `WHERE release_date_precision IN ('day','month')`。

## 二、已知数据特征（做分析前必读）

| 特征 | 数值 | 影响 |
|---|---|---|
| 唯一 `track_id` | 28,356 | 直接 `COUNT(*)` 数的是"歌曲-歌单"记录，不是歌曲数 |
| 全行完全重复 | 0 | 没有需要删的重复行 |
| 2020 年记录 | 785 行（占 2.4%） | 数据抓取时点截断，**做年度趋势请截止到 2019** |
| 专辑曲目数中位数 | 1 | 专辑维度结论较薄，不宜作主分析 |
| 歌手作品数中位数 | 1 | 10,692 位歌手，作品数 ≥3 的仅 2,486 位 |
| 音频特征与热度相关性 | 最强仅 \|r\|=0.150 | **"某特征决定热度"这类结论在这份数据上不成立** |

## 三、刻意没做的处理

| 没做 | 原因 |
|---|---|
| 不删行、不去重 | 见上文「歌单分类」 |
| 不把 `track_popularity=0` 置空 | 0 是真实值 |
| 不给只有年份的日期补月日 | 会编造数据 |
| 不使用 IQR 异常标记 | 对 `instrumentalness` 这类大量取 0 的字段，1.5×IQR 会误标 41.5% 的行 |
| 不拆歌手名 | `&` 是乐队名分隔符，拆了热度无法分摊 |
| 不填充空曲名 | 只转成 NULL，由下游决定填 `Unknown` 还是排除 |

## 四、常用查询片段

```sql
-- 歌曲数（去重口径）
SELECT COUNT(DISTINCT track_id) FROM spotify_songs;  -- 28356

-- 歌手作品数 TOP10（去重口径，供歌手维度分析参考）
SELECT track_artist, COUNT(DISTINCT track_id) n, ROUND(AVG(track_popularity),2) avg_pop
FROM spotify_songs WHERE track_artist IS NOT NULL
GROUP BY track_artist ORDER BY n DESC LIMIT 10;

-- 月度发行分布（必须先排除 year 精度，否则 1855 行会被误算进 1 月）
SELECT release_month, COUNT(DISTINCT track_id) n
FROM spotify_songs
WHERE release_date_precision IN ('day','month') AND release_month IS NOT NULL
GROUP BY release_month ORDER BY release_month;

-- 年度趋势（截止 2019）
SELECT release_year, COUNT(DISTINCT track_id) n
FROM spotify_songs WHERE release_year <= 2019
GROUP BY release_year ORDER BY release_year;
```
