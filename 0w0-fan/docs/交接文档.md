## 5. 数据库现状（实测）

连接：`mysql -uroot -p123456`，库 `spotify_dashboard`。

| 对象 | 类型 | 真实行数 | 用途 |
|---|---|---|---|
| `spotify_songs` | 表 | **32,833** | 原始数据，23 列，**永远不改、不去重、不删行** |
| `artist_track_view` | **视图** | **28,356** | 按 `track_id` 去重 + 派生 3 列，所有图表口径基于它 |
| `artist_favorite` | 表 | 6（演示数据） | 关注歌手 |
| `song_tag` | 表 | 4（演示数据） | 收藏歌曲 / 打标签 |

> Navicat 里 `spotify_songs` 显示 31,819 是 **InnoDB 估算值**，不是真实行数；`COUNT(*)` 才是 32,833。
> 视图在左侧「**视图**」节点下，不在「表」节点下。

**两张交互表的列**：

```sql
artist_favorite(id, artist_name UNIQUE, note NULL, in_dataset TINYINT, created_at)
song_tag(id, track_id, song_name NULL, tag_name NOT NULL, in_dataset TINYINT, created_at)
```

- `in_dataset`：1 = 这个名字能在 `artist_track_view` 里查到（库内），0 = 用户手输、库里没有（库外）。
  页面列表里用绿标「库内」/ 黄标「库外」区分。
- 库外的歌 `track_id` 用 `custom:歌名` 占位，歌名存进 `song_name`。
- **标签不填时存空串**（当前版本），不再自动补「收藏」。
- 视图派生列：`duration_min = ROUND(duration_ms/60000,2)`、`release_year`（只从 `^YYYY` 截取，非法格式留 NULL）、`popularity_level`（cold/low/mid/high/hot）。

**重建 / 导出**：

## 7. 前端配置（交接最容易被忽略的部分）

### 7.1 三个 JS 文件的分工

| 文件 | 职责 |
|---|---|
| `dashboard.js` | 7 张固定图 + 可配置图表（维度×度量×图表）+ 搜索面板 + KPI 翻牌 + 时钟 |
| `layout.js` | 格子布局、拖动交换、外观主题、设置弹窗、localStorage 持久化 |
| `echarts.min.js` | 第三方库，不要动 |

### 7.2 布局引擎（v3 核心）

- 舞台 1920×1080 上预划 **9 个格子（slot）**，每个格子固定位置与尺寸。
- **交换规则（当前版本）**：`kpi-strip` 是**唯一锁定**面板——可拖动但松手滑回原位、不参与交换；
  其余 8 个面板（7 张图 + 搜索面板）彼此**任意交换**格子。
- **拖动默认关闭**：必须在「自定义」弹窗里勾「允许拖动布局」才生效（防演示误触）。
  指针也只在这个开关打开时才变成「可移动」。
- 拖动是**跟手插值**（每帧 0.28 阻尼 + 轻微抬起），松手走 0.34s CSS 缓动**滑行落位**，不是瞬移。
  过渡期间每帧同步 ECharts 画布尺寸，避免「交换过去那张图显示不全」。
- 拖到别的格子时出现虚线提示框；目标格子按**鼠标落点**判定（不是按动画中面板的位置）。

### 7.3 可配置图表

中间最大位是可配置面板，三个选择器：

- **维度 8 个**：歌手分布（作品数×热度）/ 发行年份 / 歌手作品数分箱 / 专辑曲目数分箱 / 热度分档 / 歌曲时长分箱 / 歌手 TOP20 / 歌手活跃跨度 TOP20
- **度量**（按维度自动可用）：平均热度 / 最高热度 / 歌曲数 / 歌手数 / 专辑数 / 作品数 / 年份跨度 / 平均时长（分钟）
- **图表**（界面文案由「图形」改为「图表」）：气泡散点 / 面积图 / 柱状图 / 横向条形 / 环形图 / 玫瑰图

### 三方约束矩阵（v5 核心）

「维度 × 度量 × 图表」不能随便组合，两条硬约束，**双向动态过滤**（不是置灰）：

| 约束 | 内容 | 例子 |
|---|---|---|
| ① 数据形状 | 类目 62 个的时间序列只给 line/area/bar | 发行年份没有横向条形（62 行挤在 546px 里每行 8px）、没有饼图（62 个扇区无法阅读） |
| ② 图表语义 | 环/玫瑰表示「占比」，只能用可加和度量 | 选环形图后「平均热度 / 平均时长 / 最高热度」直接消失（平均值不构成整体） |

选了度量 → 不兼容的图表从下拉里消失；选了图表 → 不兼容的度量从下拉里消失。

**最终可达组合：8 维度 × 86 个组合，全部实测通过**（见 §7.4 校验脚本）。

### 7.4 组合校验脚本（答辩前跑一遍）

把下面这段贴进 F12 Console，可遍历全部可达组合并输出问题项。这是最后一次验收用的脚本，
清空 localStorage 后跑，结果应为 `total=98, bad=[]`。

```js
(function(){
  var $=function(id){return document.getElementById(id)};
  var d=$('cfg-dim'),m=$('cfg-measure'),t=$('cfg-type'),box=$('chart-custom');
  var vals=function(ser){var o=[];ser.forEach(function(s){(s.data||[]).forEach(function(v){
    if(Array.isArray(v)){v.forEach(function(x){if(typeof x==='number')o.push(x)});return}
    if(v&&typeof v==='object'){if(typeof v.value==='number')o.push(v.value);return}
    if(typeof v==='number')o.push(v)}))});return o};
  var bad=[],total=0;
  Array.from(d.options).forEach(function(do){
    d.value=do.value; d.dispatchEvent(new Event('change'));
    Array.from(t.options).forEach(function(to){
      t.value=to.value; t.dispatchEvent(new Event('change'));
      var ms=Array.from(m.options).map(function(o){return o.value});
      ms.forEach(function(mea){
        m.value=mea; m.dispatchEvent(new Event('change')); total++;
        var inst=echarts.getInstanceByDom(box);
        inst.setOption({animation:false});
        var o=inst.getOption();
        var list=inst.getZr().storage.getDisplayList(true);
        var v=vals(o.series||[]), uniq=new Set(v).size, key=0, ty=to.value;
        if(ty==='bar'||ty==='barH') key=list.filter(function(e){return e.type==='rect'&&Math.abs(e.shape.width||0)>1&&Math.abs(e.shape.height||0)>0.05}).length;
        else if(ty==='line'||ty==='area') key=list.filter(function(e){return e.type==='ec-polyline'||e.type==='ec-polygon'}).length;
        else if(ty==='pie'||ty==='ring'||ty==='rose') key=list.filter(function(e){return e.type==='sector'}).length;
        else if(ty==='scatter') key=list.filter(function(e){return e.type==='path'||e.type==='circle'}).length;
        if(v.length===0||uniq<=1||key===0) bad.push(do.value+'/'+ty+'/'+mea);
      });
      m.value=ms[0]; m.dispatchEvent(new Event('change'));
    });
  });
  console.log('total='+total, 'bad=', bad);
})();
```

**已删除的组合及原因**（都是「有这个选项但看不出任何东西」）：

| 删除项 | 原因 |
|---|---|
| 四象限的 `works` / `avgPop` 度量 | 已在 x 轴 / y 轴上，再当气泡大小是自我映射 |
| 专辑分箱的 `avgDur` 度量 | 四箱只差 9.6 秒（3.80~3.96 分），柱子几乎等高 |
| 全部雷达图 | 单度量雷达 = 柱状图弯成圆，不增加信息；20 轴 / 62 轴更是废图 |
| TOP20 / 跨度维度的饼图、环图、玫瑰图 | 排行榜不是构成比例，20 项强制聚合成 12+其它会抹掉榜尾 |
| 矩形树图、漏斗图 | 自带配色梯度与图例排布，与页面固定青蓝主题冲突 |
| **饼图**（保留环形图） | 饼与环只差一个内半径，视觉区分度不够；环形图中心还能放汇总数字 |
| **折线图**（保留面积图） | 面积图已含折线骨架，多一层渐变填充，信息量只多不少 |
- 四象限图四个象限各铺一层淡底色（青/紫/琥珀/灰蓝），气泡大小 = 专辑数。

### 7.4 搜索面板

- 一个面板、两个**分段控件**点击切换（不是下拉框），默认「按歌手搜索」**不记忆**。
- 一行四件：名称输入框 / 备注框（歌曲模式下即标签框）/ 搜索 / 动作按钮（关注 / 收藏）。
- **搜索结果浮层**：绝对定位盖在收藏列表之上，不推挤内容；放宽到 30 条、可滚轮翻。
  点一条结果 → 名字填进输入框 → 浮层收起，结果列表内容保持不变。
- 已收藏列表表格化：名称 │ 库内/库外 │ 备注/标签 │ 时间 │ 备注/删除（歌曲模式为「改标签」）。
  **备注/标签为空时显示空**，不显示「—」或「收藏」。
- 两种模式写不同表：歌手 → `artist_favorite`；歌曲 → `song_tag`。库外条目也允许保存。

### 7.5 外观与持久化

- 顶部栏两个按钮：「恢复默认」（布局+外观一起还原）、「自定义」（居中弹窗，凭空出现 + 遮罩，保存后自动关闭）。
- 弹窗里**只剩两组**（v4 精简）：面板显隐勾选、**允许拖动布局**开关。
  背景渐变 / 面板渐变 / 毛玻璃 / 面板不透明度 / 拖动方式 五组设置已全部删除，
  外观固定用 `dashboard.css` 的主题变量；拖动固定为「交换格子」。
- 全部存 `localStorage`（三把钥匙）：
  `spotify-dash-layout-v2` / `spotify-dash-theme-v3` / `spotify-dash-chart-v1`。
  「恢复默认」会清掉这些。**换机器/清浏览器缓存后布局回到默认**。

### 7.6 缓存版本号（重要）

`index.html` 里 CSS/JS 引用带 `?v=N` 查询参数。**改完前端文件必须把 N 加 1**，
否则浏览器会一直用旧缓存（本轮多次「改了没生效」都是这个原因）。当前为 **`?v=6`**。

## 8. 已知坑与注意事项（血泪清单）

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | `JAVA_HOME` 指向 JDK 21 | `mvn compile` 报 `invalid target release: 8` | 切到 `temurin8-jdk` 后重开终端 |
| 2 | 工作目录与静态路径不匹配 | `/` 返回 Whitelabel 404 | 看启动日志的「大屏静态资源检查」；`application.yml` 已列 7 个候选路径 |
| 3 | 浏览器吃旧 CSS/JS | 改了前端却没变化 | `index.html` 的 `?v=N` 加 1，或 Ctrl+F5 |
| 4 | 画布盖住顶栏 | 「自定义」「恢复默认」点不动 | 已修：画布 `z-index:1`，顶栏 `z-index:30` |
| 5 | `key` 是 MySQL 保留字 | `ERROR 1064 near 'key, loudness'` | SQL 里写 `` `key` `` |
| 6 | 排序规则错成 `general_ci` | 歌手数 10,693 → 10,684、四象限 2,486 → 2,488 | 库/表必须是 **`utf8mb4_bin`**；已修 |
| 7 | 服务端禁 `local_infile` | Navicat 导入报 `ERROR 3948` | 别改 my.ini，用 `python shared/scripts/01_import_raw.py` |
| 8 | 字面量 `NA` 造成假歌手 | `GROUP BY track_artist` 多出一个叫 NA 的 | 歌手维度查询加 `WHERE track_artist IS NOT NULL AND track_artist <> 'NA'` |
| 9 | 2020 年数据截断 | 趋势图最后一年断崖下跌 | 趋势类查询 `release_year <= 2019`（2020 仅 785 行） |
| 10 | 只有年份的日期被当 1 月 1 日 | 月份分布 1 月异常尖峰 | 视图里 `release_year` 只从 `^YYYY` 截，非法格式留 NULL，不编造 |
| 11 | 大小写敏感导致搜不到 | 输 `Nimo` 查不到 `nimo` | 搜索 SQL 用 `COLLATE utf8mb4_general_ci`；**分组统计仍用 `utf8mb4_bin`**，否则歌手数会变少 |
| 12 | 改动后端 Java 后不生效 | 新接口 404 / 旧行为还在 | **必须重启后端**（IDEA 里点 ⟳ 或重新 `java -jar`）；前端是静态文件，刷新即可 |
| 13 | 拖不动但指针变了 | 看起来能拖却拖不动 | 拖动开关默认关，去「自定义」里勾上 |
| 14 | 交换后图表显示不全 / **切换方一直闪动** | 换过去的图缺一角，或全程闪烁 | 已修（v4）：改用 FLIP —— 几何一次性落定、只 resize 一次，动画走 transform。**不要再加回逐帧 `resize()`**，那是闪烁根源 |
| 15 | TOP20 / 跨度维度「专辑数」全是 0 | 切到专辑数度量，柱长全为 0 | 已修：`ArtistTop` DTO 之前没有 `albumCount` 字段，SQL 也没查；v4 已补齐 |
| 16 | 关掉拖动后指针还是「可移动」 | 恢复默认后仍显示 move 光标 | 已修（v4）：`resetAll()` 里补了 `applyDragCursor()` |
| 17 | 四象限换度量「看起来没区别」 | 四个度量画出同一张图 | 已修（v5）：`buildScatter` 之前没接 `measure` 参数。现在专辑数走平方根压制长尾、平均时长走线性展开，两张图差 14% 像素 |
