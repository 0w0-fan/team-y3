# 大屏 v2 规划（基于 echarts-bigscreen 技能重做）

- 规划时间：2026-11-04
- 输入：v1（已在 `main`，`b924388`）+ 新装的全局技能 `echarts-bigscreen`
- 目标：把 v1 的「能跑」升级成「像大屏」——补上主视觉、KPI 翻牌、动效、单位与信息层次，同时**不破坏课程硬约束**（Spring Boot + MySQL 真实数据 + 原生前端 + 断网可用）。

---

## 一、技能与课程约束的冲突处理（先说清，这是 v2 的地基）

| 项 | 技能默认做法 | v2 采用 | 依据 |
|---|---|---|---|
| ECharts 引入 | npmmirror CDN + jsdelivr fallback | **本地 `js/echarts.min.js`**（离线分支） | 课程要求断网渲染；技能 `references/china-deploy.md` 第 2 节明确支持离线改造 |
| 数据来源 | 全部 mock 在文件内 | **后端 `/api/*` 读 MySQL 真实数据**；接口异常时显示占位而不是编造数据 | 课程要求「真实交互、增删改查落库」 |
| 交付形态 | 单文件 HTML 双击即开 | `index.html` + `css/` + `js/` 分离（仍然零构建） | 课程交付物清单要求独立 css/js 目录 |
| 图表数量 | 6~9 个（少了空、多了乱） | 5 张图 + KPI 翻牌区 + 2 个交互件 + 1 条轮播流 = 9 个模块 | 技能 `layout-patterns.md` 密度红线 |
| 数值带单位、图表带标题 | 硬性要求 | 全部照做（首 / 位 / 张 / 分 / %） | 技能第 4 步硬性要求 |
| 至少一张图带动效 | 硬性要求 | KPI 滚动 + TOP20 轮播高亮 + 底部滚动流 + 主图自动巡航 | 技能第 4 步硬性要求 |
| 配色 | 六套主题按场景选 | **暗夜紫**（科技/互联网场景） | 技能 `color-themes.md` 场景映射表 |
| 布局 | 三栏经典 左 27% / 中 46% / 右 27% | 采用 | 技能 `layout-patterns.md` 布局 A |
| 顶部标题栏 | h=72px，居中大标题 + **实时时钟** | 采用（v1 缺时钟） | 技能骨架规范 |

一句话：**拿技能的美术与结构规范，套课程的真实数据链路。**

## 二、v1 的问题（v2 要解决的）

1. **没有主视觉**：中栏是一张普通散点，缺少"这是大屏"的第一眼冲击。
2. **没有 KPI 翻牌区**：关键数字挤在顶部标题栏的小方块里，字号不够、没有单位、没有滚动动画。
3. **没有时间维度**：6 张图全是横截面，缺一张逐年趋势（数据里有 1957–2019 的年份，白白浪费）。
4. **动效为零**：整屏静止，技能明确要求"至少一个图表带动效"。
5. **配色是自定义青蓝**，不是成套主题变量，系列色不统一。
6. **信息层次平**：卡片标题一样大，没有主次；右侧交互区偏挤。

## 三、v2 设计

### 3.1 主题：暗夜紫

```css
:root{
  --bg-main:#12082e; --bg-panel:rgba(38,20,74,.55);
  --border-glow:#5b3fa8; --text-title:#f3edff;
  --text-main:#cfc2ee; --text-sub:#8a76b8;
  --accent:#a06bff; --accent-warn:#ffb84d; --accent-danger:#ff5f8f;
}
const SERIES_COLORS = ['#a06bff','#5e60ce','#00d4ff','#f72585','#4cc9f0','#ffd166'];
```

底色带紫相（不用纯黑），标题用带色温的白，系列色不超过 6 种——全部按技能 `color-themes.md` 的通用禁忌执行。

### 3.2 布局：三栏经典（左 27% / 中 46% / 右 27%）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部标题栏 h=72   Spotify「产量-热度」效率分析   2026-11-04 20:15:33 │
├──────────────┬──────────────────────────────┬────────────────┤
│ 左 27%        │ 中 46%                        │ 右 27%          │
│ ① 逐年趋势     │ ⓪ KPI 翻牌区 h≈110（5 个）      │ ④ 年份跨度       │

│ ② 长尾分布     │ ⑥ 底部窄条·关注/标签滚动流       │ ⑥ 歌曲打标签（写库）│
│ ③ TOP20 热度   │                               │                │
└──────────────┴──────────────────────────────┴────────────────┘
```

### 3.3 九个模块的口径（全部真数据）

| # | 模块 | 图表配方 | 数据来源 | 口径 |
|---|---|---|---|---|
| ⓪ | KPI 翻牌 5 个 | 数字滚动 1.2s easeOut | `/api/overview` | 去重歌曲 28,356 首 / 歌手 10,693 位 / 专辑 19,744 张 / 平均热度 42.48 / 关注+标签 实时 |
| ① | 逐年歌曲数 + 平均热度 | 技能配方 1 流光折线 + 配方 5 双轴 | **新接口** `/api/year/trend` | x=发行年（**截止 2019**，2020 仅 785 行是抓取截断）；柱=歌曲数，线=平均热度；窗口内自动巡航 |
| ② | 歌手作品数长尾分布 | 渐变圆角柱（y 对数） | `/api/artist/distribution` | 8 箱：1/2/3/4/5/6-10/11-20/21+，y 轴对数 |
| ③ | 平均热度 TOP20 | 横向渐变条 + **轮播高亮** | `/api/artist/top?limit=20` | 作品数 ≥ 3，按平均热度降序 |
| ④ | 歌手活跃年份跨度 | 横向堆叠条（透明底 + 跨度） | `/api/artist/span?limit=20` | 作品数 ≥ 3 且年份非空，按跨度取前 20 |
| ⑤ | **主视觉** 作品数 × 平均热度四象限 | 散点 + markLine + markArea | `/api/artist/quadrant` | 2,486 位歌手；x=作品中位数 5，y=均值 42.48；点大小映射专辑数（新增字段） |
| ⑥ | 底部窄条 关注/标签流 | 技能配方 7 纯 DOM 无缝滚动 | **新接口** `/api/activity/recent` | 最近 20 条关注与标签，`document.hidden` 时暂停 |
| ⑦ | 关注歌手 | 表单 + 列表（增/改/删） | `/api/favorite` | 写库，唯一索引防重 |
| ⑧ | 歌曲打标签 | 搜索 + 选中 + 标签芯片 | `/api/tag`、`/api/song/search` | 写库，同歌同标签唯一 |

交互件从 v1 的"右侧小面板"升级为**带单位的卡片**，并接进底部滚动流（操作后立即出现在流里，答辩演示更直观）。

### 3.4 v2 新增的后端接口（3 个）

| 接口 | SQL 口径 | 用途 |
|---|---|---|
| `GET /api/year/trend` | `SELECT release_year, COUNT(DISTINCT track_id) songs, ROUND(AVG(track_popularity),2) avgPop FROM artist_track_view WHERE release_year BETWEEN 1957 AND 2019 GROUP BY release_year ORDER BY release_year` | 流光折线 + 双轴 |
| `GET /api/activity/recent?limit=20` | 关注表与标签表 `UNION ALL` 取最近 20 条（带类型与时间） | 底部滚动流 |
| `GET /api/artist/quadrant`（增强） | 增加 `albumCount` 字段：该歌手去重专辑数 | 主图点大小 |

其余 6 个接口口径不变，避免动到已经验收通过的部分。

### 3.5 动效清单（技能硬性要求）

1. KPI 数字 0 → 目标值滚动（1.2s，easeOut）
2. TOP20 条形每 2.4s 轮播高亮
3. 底部关注/标签流无缝滚动（`document.hidden` 暂停，防后台空转）
4. 逐年趋势图 dataZoom 窗口自动巡航
5. 主视觉散点入场动画（`animationDuration: 1200`）

### 3.6 性能红线（技能 `china-deploy.md` 第 6 节）

- 单屏 ECharts 实例 5 个（≤10），28,356 点的图继续用 `large: true`
- 所有 `setInterval` 集中注册，标签页隐藏时统一暂停
- 数据刷新用 `setOption` 增量更新，不销毁重建实例
