## 二、数据链路（从 CSV 到大屏）

```
shared/raw/spotify_songs.csv            32,833 行 × 23 列（7.6 MB，不进 git）
        │  ① 第一阶段：只导入不清洗（shared/scripts/01_import_raw.py）
        ▼
MySQL  spotify_songs                    主表，32,833 行，utf8mb4_bin
        │  ② 第二阶段：按 track_id 去重 + 派生 3 列（0w0-fan/data/02_build_view.sql）
        ▼
MySQL  artist_track_view（视图）        28,356 行 = 真正的歌曲数
        │  ③ 后端：MyBatis 注解 SQL 统计（mapper/SongMapper.java）
        ▼
Spring Boot  /api/*  13 个接口          JSON（最大 502 KB，0.13 s）
        │  ④ 前端：fetch 取数 → ECharts（js/dashboard.js）
        ▼
ECharts  5 张图 + KPI 翻牌区            全部真实数据，断网可用
```

**为什么要有第 ② 步**：主表里 4,477 行是「同一首歌被多个歌单收录」产生的重复记录，
它们只有 4 个歌单字段不同，歌曲本身的热度与音频特征完全一致。
直接 `COUNT(*)` 数的是「歌曲-歌单」记录（32,833），不是歌曲数（28,356）。
去重**不删主表任何一行**，而是建视图 `artist_track_view`——原始数据永远保留。

**两个交互件**是反向写库：

```
页面「关注歌手」→ POST /api/favorite → FavoriteService → FavoriteMapper → 表 artist_favorite
页面「打标签」  → POST /api/tag      → TagService      → TagMapper      → 表 song_tag
```

## 四、后端分层与调用关系

```
浏览器
  │ HTTP
  ▼
Controller（接口层）      只负责：接参数 → 调 Service → 返回对象；不写业务、不写 SQL
  │
  ▼
Service（业务层）         口径、校验、事务、结构组装（例如给 TOP 榜补名次 rank）
  │                       校验失败抛 BizException，由 GlobalExceptionHandler 统一转 JSON
  ▼
Mapper（持久层）          MyBatis 注解 SQL；口径（去重、过滤 NA、分箱）都写在 @Select 上
  │
  ▼
MySQL                    artist_track_view（读） / artist_favorite、song_tag（写）
```

一次具体调用（点一次「关注」）：

```
点击按钮
 → dashboard.js  addFavorite()
 → POST /api/favorite {artistName, note}
 → FavoriteController.create(req)
 → FavoriteService.create()          校验非空/长度/是否 NA → 查重 → insert → 回读取整行
 → FavoriteMapper.countByArtist() / insert() / findById()
 → MySQL artist_favorite
 ← 返回 201 + 完整记录（id、createdAt）
 → 前端刷新关注列表 + KPI 里的「关注」计数；Navicat 里能看到新行
```

## 五、图表口径对照表（答辩最常被问的部分）

所有统计基于**去重视图**（28,356 行），歌手维度排除空值与字面量 `NA`。

| # | 图表（页面位置） | SQL（`SongMapper` 方法） | 口径 | 期望数据量 | 前端函数 |
|---|---|---|---|---|---|
| 1 | 逐年歌曲数 × 平均热度（左上） | `selectYearTrend` | 按 `release_year` 分组统计歌曲数与平均热度，默认 1957–2019 | 62 年 | `renderTrend` |
| 2 | 歌手作品数长尾分布（左中） | `selectArtistDistribution` | 作品数分箱 1/2/3/4/5/6-10/11-20/21+，y 轴对数 | 8 箱 | `renderDistribution` |
| 3 | 平均热度 TOP20（左下） | `selectTopArtists` | 作品数 ≥ 3，按 `AVG(track_popularity)` 降序 | 20 位 | `renderTop` |
| 4 | 歌手活跃年份跨度（右上） | `selectTopSpans` | `MAX(release_year) − MIN(release_year)`，作品数 ≥ 3，取前 20 | 20 条 | `renderSpan` |
| 5 | **四象限气泡（中，主视觉）** | `selectQuadrant` | x = 作品数，y = 平均热度，气泡大小 = 专辑数；分割线 x 中位数 5 / y 均值 42.48 | **2,486** 点 | `renderQuadrant` |
| 6 | 专辑曲目数 × 歌曲热度（右下） | `selectAlbumBins` | 曲目数 ≥ 2 的专辑分箱，y = 箱内歌曲平均热度（歌曲加权） | 4 箱 | `renderAlbum`※ |
| 7 | 热度 × 时长全量散点 | `selectPopularityDuration` | 全量点，`large: true` | 28,356 点 | `renderScatter`※ |

※ 图 6 在 v2 页面中被图 5（主视觉）取代，接口与口径保留；图 7 的散点接口同样保留。
**当前 v2 页面实际渲染 5 张图**：逐年趋势、长尾分布、TOP20、年份跨度、四象限气泡。

三个容易踩的点（都已在代码注释里写明）：

1. **`key` 是 MySQL 保留字**，SQL 里必须写成 `` `key` ``。
2. **歌手名里有字面量 `NA`**（原始数据缺失值写法），分组统计必须排除，否则会多出一位「假歌手」。
3. **2020 年只有 785 行**（抓取时点截断），趋势图默认截止 2019，否则最后一年断崖式下跌。

## 六、代码注释规范（本项目的写法）

注释要求：**说明「为什么」，而不是重复「做什么」**；每个文件、每个公开方法都要有。

| 位置 | 写法 | 例子 |
|---|---|---|
| Java 类 | Javadoc：这个类属于哪一层、负责什么、有什么约定 | `ChartService`：「六张图表的取数逻辑。所有口径见 README」 |
| Java 方法 | Javadoc：做什么 / `@param` / `@return` / 抛什么异常 | `FavoriteService.create()` 写了 400 与 409 两种失败 |
| Java 行内 | 只写「为什么这么写」 | 为什么中位数在 Java 里算而不是写在 SQL 里 |
| MyBatis SQL | 在 `@Select` 上方注明口径与期望行数 | `selectQuadrant` 注明「结果稳定为 2,486 行」 |
| HTML | 区块注释 `<!-- ===== 三栏 ===== -->` | index.html 按「顶栏 / 左栏 / 中栏 / 右栏」分段 |
| CSS | 分节注释 + 关键属性说明 | 卡片四角装饰用 background 渐变一次画四个角的原因 |
| JS | 函数级说明 + ECharts 配置逐项中文解释 | 每个 `renderXxx` 开头写明「横轴/纵轴/系列/交互」 |
| SQL 脚本 | 脚本头（用途 / 口径 / 执行方式 / 校验 SQL） | 02_member_view.sql 头部写明目标行数 28,356 |

约定：**getter/setter 与 DTO 的空构造方法不写注释**（没有信息量），
第三方库的配置（`application.yml` 里的 Druid 参数、`pom.xml` 的依赖版本）只在必要时加说明。

## 八、怎么跑（最短路径）

```powershell
# 1. 切 JDK 8（本机默认是 21，不切会报 invalid target release: 8）
$env:JAVA_HOME='C:\Users\Fan\scoop\apps\temurin8-jdk\current'
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"
java -version            # 必须是 1.8.0_504

# 2. 起后端（IDEA 里直接点运行也可以，端口 8088）
cd D:\Project\IDEA\team-y3\0w0-fan\backend
mvn spring-boot:run

# 3. 打开大屏
#    浏览器访问 http://localhost:8088/
```

启动日志里会有一行「大屏静态资源检查」，列出前端目录的绝对路径与命中情况——
如果 `/` 返回 404，先看这行。

**常见问题**：

| 现象 | 原因 | 处理 |
|---|---|---|
| `/` 返回 Whitelabel 404 | 工作目录不在候选路径里，前端目录没挂上 | 看启动日志的前端目录检查；在 IDEA 里重启即可（v2 已支持 7 个候选路径） |
| `mvn compile` 报 `invalid target release: 8` | `JAVA_HOME` 指向 JDK 21 | 按上面第 1 步切到 JDK 8 |
| Navicat 里看不到视图 | 视图在左侧「**视图**」节点下，不在「表」节点 | 展开「视图」→ `artist_track_view` |
| Navicat 显示主表 31,819 行 | 那是 InnoDB 的**估算值** | `SELECT COUNT(*)` 得到真实的 32,833 |
| 页面图表空白 | 后端没起或接口报错 | F12 → Network 看 `/api/*` 是否 200 |
